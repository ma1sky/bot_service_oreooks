# Bot Service (Telegram бот ОреОКС)

## 1. Название и назначение сервиса

Telegram бот "ОреОКС" – интерфейс для взаимодействия студентов с учебными данными (расписание, контрольные мероприятия, личные задачи). Бот предоставляет интерактивное меню, позволяет просматривать расписание на любой день, управлять задачами и получать уведомления о событиях.

Основные функции:

- Аутентификация через ORIOKS (ввод токена).
- Просмотр расписания занятий с навигацией по дням.
- Просмотр контрольных мероприятий (событий) с навигацией по дням.
- Управление персональными задачами (создание, редактирование, удаление, отметка выполнения).
- Главное меню с быстрым доступом ко всем разделам.

## 2. Архитектура и зависимости

- **Технологии и фреймворки:** Node.js, TypeScript, Telegraf (фреймворк для Telegram ботов), Zod для валидации, ioredis для работы с Redis, BullMQ для очередей (пока не используется активно).
- **Взаимодействие с другими микросервисами:**
    - Общается с API Service через HTTP-запросы для получения расписания, событий и управления задачами.
    - Использует Redis как хранилище сессий пользователей (состояние сцены, шаг, черновики задач).
- **Используемые внешние сервисы:**
    - Telegram Bot API (через Telegraf).
    - Redis – хранение сессий и, потенциально, кэширование.
    - API Service (отдельный микросервис) – источник данных.

## 3. Способы запуска сервиса

### Локальный запуск через Docker

```bash
cd bot_service
docker build -t bot_service .
docker run -p 3000:3000 bot_service
```

### Альтернативный запуск без Docker

1. Установите зависимости:
    ```bash
    npm install
    ```
2. Создайте файл `.env` на основе `.env.example` и заполните переменные окружения:
    ```env
    BOT_TOKEN=your_telegram_bot_token
    API_SERVICE_LINK=http://localhost:3000  # URL API Service
    REDIS_URL=redis://localhost:6379
    ```
3. Соберите проект:
    ```bash
    npm run build
    ```
4. Запустите бота:
    ```bash
    npm start
    ```

### Переменные окружения

- `BOT_TOKEN` – токен вашего Telegram бота, полученный от @BotFather (обязательно)
- `API_SERVICE_LINK` – базовый URL API Service (по умолчанию http://localhost:3000)
- `REDIS_URL` – строка подключения к Redis (по умолчанию redis://localhost:6379)

## 4. API документация

Бот не предоставляет REST API, но использует внутреннюю маршрутизацию на основе сцен (Telegraf scenes). Основные сцены (состояния) бота:

- `authScene` – аутентификация пользователя.
- `menuScene` – главное меню с кнопками выбора раздела.
- `tasksScene` – управление задачами (просмотр, создание, редактирование).
- `scheduleScene` – просмотр расписания с навигацией по дням.
- `eventsScene` – просмотр контрольных мероприятий с навигацией по дням.

Каждая сцена имеет свой обработчик (`Handler`), который реагирует на callback-запросы инлайн-клавиатуры и текстовые сообщения.

## 5. Как тестировать

- Запуск unit-тестов: `npm test`
- Запуск тестов с покрытием кода: `npm run test:coverage`
- Запуск тестов в watch-режиме: `npm run test:watch`

Тесты расположены в директории `src/**/__tests__/` и используют Jest.

### Структура проекта

```
src/
├── auth/          # Аутентификация
├── menu/          # Главное меню
├── tasks/         # Управление задачами
├── schedule/      # Расписание
├── events/        # Контрольные мероприятия
├── base/          # Базовые классы (Handler, Service)
├── config/        # Конфигурация, типы
├── session/       # Работа с Redis-сессиями
├── router/        # Маршрутизатор между сценами
└── index.ts       # Точка входа
```

### Разработка новых модулей

Для добавления новой функциональности (например, модуля "уведомления") следует:

1. Создать директорию в `src/` с файлами `handler`, `service`, `schema`, `types`, `messages`.
2. Зарегистрировать обработчик в `src/router/router.ts`.
3. Добавить кнопку в главное меню (`src/menu/menu.messages.ts`).
